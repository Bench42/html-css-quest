## Что это
Серия браузерных игр-курсов, где человек без опыта учит программирование как игру. Первая игра, Python Quest, готова и понравилась другу Максима, который не программист и играл около двух часов подряд. Дальше курсы по HTML/CSS (в работе), JS, React, бэкенд. Автор: Максим (учится вместе с Claude, нулевой бюджет). Главная цель Максима: развиваться, осваивать современные инструменты и наращивать скилы для фриланса; при успехе проект можно монетизировать.

## Python Quest v2: что есть
- 8 локаций + босс, 47 заданий. Локации: 1 Деревня (print), 2 Тёмный лес (переменные), 3 Река (числа и арифметика), 4 Пещера (строки и f-строки), 5 Мост (if, elif, else), 6 Башня (циклы), 7 Рынок (списки), 8 Замок (функции), Логово дракона (босс).
- Python выполняется в браузере через Pyodide 0.26.4 (CDN jsdelivr) в Web Worker из Blob. Таймаут 6 секунд.
- Каждый урок разобран построчно. У каждого задания три подсказки, третья это решение.
- XP: первое задание локации 100, остальные 50, босс 150; каждая подсказка снижает награду на 20, минимум 40%. 300 XP на уровень, 8 рангов. Режим «тренировка» со случайными заданиями.
- Сохранение: localStorage, ключ pq_save2.
- Устройство python-quest.html: `/*LEVELS_START*/…/*LEVELS_END*/` данные курса (помощник `T(task, starter, check, h1, h2, solution, extra)`, `const LOCS`); `/*HARNESS_START*/…/*HARNESS_END*/` обвязка на Python (`__run(code, check)`, в проверке `out`, `src`, `lines`, `rerun(var, val)`); остальное JS карты, подсказок, XP.
- Тестирование: для каждого задания эталон проходит проверку, заготовка нет (все 47 проходили).

## Серия: мир «Город Кода» (решено 25.10.2026)
Все курсы серии живут в одном мире. Герой (мужчина; выбор пола, если понадобится, позже) приходит в Город Кода, где по легенде куча возможностей. Чтобы стать своим и получить гражданство, нужно сдать городскому совету лендинг. В городе есть кланы: **HTML/CSS** это первый и самый простой клан, он принимает героя после сдачи лендинга. Чтобы подняться выше, нужно пройти путь JS, потом React, потом бэкенд (каждый курс это отдельная игра и отдельный клан).
- Наставник: дух программиста, объясняет тему и примеры, даёт то, чего не хватает в реальной жизни. Имя и характер не выбраны.
- Один и тот же сайт проходит через всю серию (см. «Торг-Хаб»).

## HTML/CSS Quest: новая концепция (25.10.2026)
**Причина пересмотра:** рисованные рамки, свитки и карта получались кривыми, слишком много экранов и картинок. Сюжет про таверну, мастеров, наследство дяди Флекса, карту города и пергаментные рамки отменены.

**Экран (один, как референс «Web Odyssey»):** слева/сверху сцена: фон-картинка под ситуацию и реплика персонажа в облачке. Справа/ниже четыре вкладки: **Наставник** (объяснение темы, примеры, подсказки), **HTML**, **CSS**, **Лендинг** (живой результат). В каждой сцене меняются только тексты, задание и картинки. После верного решения сцена меняется (закрытые ворота становятся открытыми) и появляется кнопка перехода на следующую локацию. Интерфейс (вкладки, редакторы, кнопки) делается в CSS, не картинками. На телефоне сцена сверху, вкладки ниже.

**Экономика:** ошибка при проверке отнимает HP (набор кода не штрафуется), HP восстанавливается за деньги, деньги даёт выполнение заданий. HP списывается только на экзамене (в тренировке нет). Бесплатные подсказки только в примерах Духа Перемен; на экзамене игрок решает сам, но может купить подсказку за монеты, чтобы не терять HP. Цена подсказки: 25% от текущих монет игрока (округляем вверх до целого); если на счёте меньше 25 монет, купить подсказку нельзя. При нуле HP проверка блокируется, прогресс не обнуляется: игрок берёт мелкий повторный заказ ради денег. Стартовые числа для тестирования: HP 100, ошибка −10, лечение 20 HP за 30 монет, экзамен +60, тренировочное задание +15, мелкий заказ +20. Если монет будет оставаться много, придумаем, на что их тратить (например, кастомизация сайта).

**Лендинг «Торг-Хаб»:** вымышленный магазин в Городе Кода (одна компания для всех игроков, без персонализации). Лендинг работает как раскраска (подробно в разделе «Лендинг: раскраска и картинки» ниже). В конце игрок скачивает готовый сайт как zip-архив (index.html, style.css, папка images), который открывается двойным кликом. При скачивании игра сама добавляет в подвал штамп «Собрано в Code Quests» со ссылкой на игру как знак пройденного финального задания; игрок не пишет его сам. Полной защиты от удаления на статической странице нет, это принято; настоящая проверка штампа по номеру возможна позже в бэкенд-части. Картинки игры можно использовать на скачанном сайте.

**Рост «Торг-Хаба» по серии:** HTML/CSS даёт вёрстку; JS: корзина, фильтры, поиск, проверка формы; React: компоненты, страницы, состояние корзины; бэкенд: приём заказов, база, письма на почту, админка (сюда же ложится конфигуратор магнитов Максима). В конце всех игр сайт выкладывается на GitHub как полностью рабочий проект в стиле игры, как будто вынутый из неё: работа в портфолио и бесплатная реклама игры. Максим берёт из него знания и для своего магазина магнитов. GitHub Pages даёт только статику; заказы и письма пойдут через бесплатные сервисы (например, Supabase, Resend или EmailJS), без реальных платежей.

**13 сцен (блок сайта ↔ место в городе ↔ тема).** В 1-й сцене игрок пишет только теги; классы вводятся во 2-й сцене у Красильщицы (мастер по стилям).
1. Ворота: Hero, название и слоган: h1, p, b (вступление Наставника: что такое HTML и CSS; отступы и положение блока стоят «за героя», заголовок встаёт на место, но чёрно-белый; Наставник отправляет к Красильщице)
2. Красильня: class и оформление Hero: class, color, background, font (игрок вешает class на заголовок, и он становится цветным; ломать здесь нечего)
3. Площадь: «О рынке» и преимущества: h2, ul, li (оформление через классы)
4. Указатели: промо-полоска, шапка и меню: a, nav, :hover
5. Лавка художника: баннер и картинки: img, max-width (первая сцена, где игрок пишет пути к картинкам)
6. Каркас: структура страницы: header, main, section, footer
7. Окно заказов: форма заказа и подписка: form, input, button
8. Каменщик: карточки товаров, мини-босс «Лорд Переполнения»: padding, margin, border, overflow, box-sizing
9. Караван: полоса цифр, меню и категории в ряд: flexbox
10. Мастерская шаблонов: товары и отзывы, повтор карточек, несколько классов на элементе, приоритет селекторов
11. Склад: категории и витрина сеткой: grid
12. Дорога: мобильная версия: media queries
13. Совет города: FAQ, подвал в колонки, сдача сайта, финальный босс (чинить и дополировать всё сразу), штамп и приём в клан

Идея из «Кодекса Архитектора» остаётся: в CSS-сценах задания «код меняет мир» (код → объект в превью).

**Механика кода (из прежней версии, остаётся):** игрок печатает код сам; над клавиатурой кнопки тегов (тап вставляет пару, курсор внутрь, вложенность, выделенное оборачивается, «↵ выйти»); только изученные теги; ошибки с точным техническим сообщением; проверка по структуре через DOMParser (парность и порядок, нужные теги, вложенность, текст, е=ё), для CSS проверка по computed style; превью в Shadow DOM с очисткой (script, iframe, on*-атрибуты). Сохранение: localStorage, новый ключ (hcq_save2 или новый, решает код).

## Лендинг: раскраска и картинки (решено 25.10.2026)
**Макет:** Максим сгенерировал в Nano Banana макет «Торг-Хаба» в пиксель-арте (стиль одобрен: «именно тот, что я хотел»). Макеты положить в `reference/art/landing/` как ориентир (тексты на них местами искажены нейросетью, настоящие тексты пишем кодом). Блоки макета сверху вниз: промо-полоска, шапка и меню, hero с панорамой рынка, полоса цифр (4 показателя), «О рынке» с иконками и иллюстрацией, категории (6 плиток), «Как это работает» (3 шага), баннер акции («Неделя механических сов»), товары (8 карточек), отзывы (3 карточки с портретами), FAQ (5 вопросов), новости и форма заказа, подвал в колонки со штампом «Собрано в Code Quests».

**Раскраска.** Вкладка «Лендинг» сразу показывает всю страницу. Весь макет «Торг-Хаба» с самого начала виден чёрно-белым и стоит на местах (видна цель). Когда игрок проходит блок (экзамен сцены), он становится цветным и встаёт на место; блок вспыхивает. Цвет блок получает в сцене, где изучаются нужные стили (заголовок после сцены 1 чёрно-белый, цветным становится после сцены 2). После сцены 1 заголовок стоит на месте (отступы «за героя»), но чёрно-белый; Наставник отправляет к Красильщице, и после сцены 2 он цветной; дальше оформление растёт по сценам: цвет и шрифты в 2-й, блочная модель в 8-й, раскладка в 9–11-й, адаптив в 12-й, и страница превращается в пиксельный макет. Нашу версию каждого блока пишем как эталон для проверки.

**Картинки и пути.** Все картинки лежат внутри игры в готовой папке с понятными именами (`images/owl.png`, `icons/coin.png`). Игрок пишет только путь к картинке (`<img src="images/owl.png" alt="Сова">`), ничего не скачивая; это и есть практика относительных путей. Это рутина, но осознанная: главное, чтобы было понятно, что брать, где лежит и как выглядит путь. Для этого на вкладке «Наставник» есть «склад картинок» (список имён с миниатюрами и готовым путём) и пошаговое объяснение путей. Картинки сначала стоят чёрно-белыми на местах, пути к ним прописаны «за героя». В сцене 5 (img) после кнопки «Понял» пути рушатся (картинки ломаются), и игрок восстанавливает их сам, но только для картинок своей сцены (около 5 штук: баннер, иллюстрация «О рынке», сова и т. п.); после этого картинки становятся цветными. В следующих сценах с новыми картинками пути снова входят в экзамен (по 1–3 штуки), чтобы навык закреплялся без монотонности.

**Цикл сцены (решено 25.10.2026):** 1) вкладка «Наставник»: объяснение и примеры (подсказки только здесь); 2) тестовые задания на похожих примерах (тренировка); 3) кнопка «Понял»: переносит на экзамен и убирает заготовленную структуру, которая стояла «за героя» (например путь к картинке, отступы, раскладка); 4) экзамен: главное задание сцены, где игрок сам пишет или восстанавливает убранное; 5) блок становится цветным и встаёт на место, сцена меняется, открывается переход. Экзамен это и есть главное задание сцены, поэтому заданий не вдвое больше. В сценах, где «ломать» нечего (например заголовок в сцене 1), экзамен просто задание сцены. Заготовленные строки видны игроку (с пометкой, что их написал город), поломка это событие истории, HP за неё не списывается. Механики «за героя» берём там, где это даёт эффект: отступы (стоят «за героя» с первой сцены, в сцене 8 рушатся: заголовок и блоки ломаются, игрок восстанавливает), flexbox (сцена 9), grid (сцена 11), адаптив (сцена 12), пути к картинкам (сцена 5). HP списывается только на экзамене, в тренировке нет; точные числа подберём при тестировании.

**Как ведём игрока в сцене с путями (сцена 5, без «угадывания»):** пример на вкладке «Наставник» разбирает один путь по частям (папка, имя файла, расширение) на картинке из склада; задание разбито на 3 шага (одна картинка с alt, ещё две, остальные), следующий шаг открывается после предыдущего; в «Нужно» для каждой картинки написано, куда она идёт и что на ней, склад рядом показывает миниатюры с именами; ошибки точные («файла images/ovl.png нет в складе, проверь имя»), HP за такие опечатки не списывается; превью показывает картинку при верном пути и значок поломанной при неверном.

**Скачивание:** zip-архив (index.html, style.css, images/) с автоматическим штампом в подвале.

**Список картинок (около 50, генерируем листами на однотонном фоне, вырезает Claude):**
- Фоны сцен: 13 штук; плюс состояние «открыто» (две картинки) только для ворот и, возможно, пары сцен; остальное оживляем в CSS.

- Решено: испытание у ворот = починка вывески «Торг-Хаба»: стражник просит починить вывеску, игрок пишет h1 с названием, p со слоганом, b для акцента; отступы и положение блока стоят «за героя», надпись «Торг-Хаб» встаёт на место, но остаётся чёрно-белой; Наставник отправляет к мастеру по стилям (Красильщице, сцена 2), где игрок вешает class, и заголовок становится цветным. Во вступлении Наставник сразу объясняет, что HTML это скелет страницы, а CSS её одежда. Решено: героя зовут «Новичок», своё имя игрок вписывает в конце в готовый сайт (подпись автора); Наставник это Дух Перемен. Для скачанного сайта читаемость как у обычного магазина важнее игровых отсылок; диалоги и персонажи на сайт не попадают.

## Стек и способ работы (решено 25.10.2026)
- Vite + React (JavaScript, TypeScript позже), Tailwind CSS (v4 через @tailwindcss/vite), позже CodeMirror 6, PWA, публикация на GitHub Pages через GitHub Actions. Бесплатно, без серверов.
- Playwright стоит как dev-зависимость для автопроверок.
- Среда Максима: Windows, VS Code, Git 2.55 (скрытый адрес GitHub), Node 24, npm 11. В облачной среде Claude npm заблокирован (403): собрать Vite там нельзя.
- Работа в паре: Максим выполняет команды и понимает, что, зачем и как; Claude объясняет простыми словами. Код пишет Claude Code в VS Code (читает CLAUDE.md в корне репозитория, не видит чат). Этот чат для обсуждения, дизайна, ревью планов. Правила: команды описываются по-русски простыми словами, временные файлы в `.tmp` (в .gitignore), без согласия ничего не удаляется и не ставится вне плана; Максим одобряет безопасные команды (чтение, lint, build) и читает всё, что удаляет, ставит, делает push.
